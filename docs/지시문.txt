트립메이트 Android 앱 구현을 진행해줘.

단, 바로 큰 기능을 한 번에 구현하지 말고 아래 원칙을 반드시 지켜줘.

1. 작업 전 확인
- 현재 프로젝트 구조를 먼저 확인해줘.
- AGENTS.md와 docs 문서를 먼저 읽고 요구사항을 기준으로 구현해줘.
- 기존에 빌드 성공한 상태를 깨뜨리지 않도록 작은 단위로 작업해줘.
- google-services.json, 패키지명 com.tripmate.app, Firebase 설정이 유지되는지 확인해줘.

2. 구현 범위
- 한 번에 너무 많은 기능을 구현하지 말고 기능 단위로 나눠서 진행해줘.
- 각 단계마다 빌드가 성공하는지 확인해줘.
- 우선순위는 다음 순서로 진행해줘.
  1) Google 로그인
  2) 로그인 상태 유지
  3) Firestore users 문서 저장
  4) 여행 목록 화면
  5) 여행 생성 화면
  6) 초대 코드 참여
  7) Day별 일정 관리
  8) 준비물 관리
  9) 외부 지도 앱 실행

3. 빌드 안정성
- Gradle, AndroidX, Firebase, Compose 의존성 버전은 서로 호환되도록 확인해줘.
- 새 라이브러리를 추가해야 할 경우 이유를 설명하고 최소한으로 추가해줘.
- build.gradle.kts 수정 후 반드시 Gradle 빌드를 실행해줘.
- local.properties, google-services.json 같은 로컬/민감 파일은 실수로 삭제하거나 덮어쓰지 마.
- 불필요한 리팩토링은 하지 말고 현재 단계에 필요한 코드만 수정해줘.

4. 테스트 기준
- 구현 후 반드시 다음 명령으로 빌드 검증해줘.
  ./gradlew assembleDebug
- 가능한 경우 다음 테스트도 실행해줘.
  ./gradlew test
  ./gradlew connectedAndroidTest
- 에뮬레이터나 연결된 Android 기기가 있으면 실제 앱 실행 테스트까지 진행해줘.
- 실제 실행 테스트에서는 최소한 다음을 확인해줘.
  - 앱이 정상 실행되는지
  - 로그인 화면이 표시되는지
  - Google 로그인 버튼을 눌렀을 때 계정 선택 또는 로그인 흐름이 시작되는지
  - 로그인 성공 후 사용자 정보가 Firestore users 컬렉션에 저장되는지
  - 앱을 재실행했을 때 로그인 상태가 유지되는지

5. 오류 대응
- 빌드 오류가 나면 오류 메시지를 먼저 분석하고 원인을 설명해줘.
- 임시방편으로 무작정 버전을 낮추거나 기능을 제거하지 말고, 원인을 확인한 뒤 수정해줘.
- Firebase 관련 오류가 나면 SHA-1/SHA-256, google-services.json, Authentication 설정, 패키지명을 순서대로 점검해줘.
- Android 실행 오류가 나면 Logcat 또는 Gradle 오류를 근거로 수정해줘.
- 테스트를 못 한 항목이 있으면 이유와 남은 확인 방법을 알려줘.

6. UI 기준
- 모바일 우선으로 구현해줘.
- 화면 요소가 겹치지 않도록 해줘.
- 카드형 UI를 쓰되 너무 복잡한 관리자 화면처럼 만들지 마.
- 텍스트가 버튼이나 카드 밖으로 넘치지 않게 해줘.
- 밝고 깔끔한 여행 앱 느낌을 유지해줘.

- 실제 기기/에뮬레이터 테스트 여부를 알려줘.
