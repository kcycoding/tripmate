# 화면 및 UI 설계

## 디자인 원칙

- 모바일 우선으로 설계한다.
- 밝고 깔끔한 여행 앱 느낌을 유지한다.
- 날짜별 일정이 한눈에 보여야 한다.
- 카드형 UI를 사용하되 화면을 복잡한 관리자 도구처럼 만들지 않는다.
- 처음 사용하는 사람도 주요 버튼의 의미를 쉽게 이해할 수 있어야 한다.

## 화면 목록

- 스플래시 화면
- 로그인 화면
- 여행 목록 화면
- 여행 생성 화면
- 초대 코드 참여 화면
- 여행 상세 화면
- Day별 일정 화면
- 일정 추가/수정 화면
- 전체 일정 화면
- 준비물 화면
- 여행 설정 화면

## 스플래시 화면

역할:

- 앱 시작 상태 표시
- 로그인 여부 확인

동작:

- 로그인된 사용자는 여행 목록 화면으로 이동한다.
- 로그인되지 않은 사용자는 로그인 화면으로 이동한다.

## 로그인 화면

구성:

- 앱 이름 `트립메이트`
- 간단한 설명 문구
- Google 로그인 버튼

동작:

- Google 로그인 성공 시 사용자 정보를 저장하고 여행 목록으로 이동한다.

## 여행 목록 화면

구성:

- 상단 앱 바
- 내 여행 목록
- 여행 생성 버튼
- 초대 코드로 참여 버튼

여행 카드 표시 정보:

- 여행 제목
- 여행지
- 여행 기간
- 여행 상태
- 멤버 수
- 기본 지도 앱

여행 상태:

- 여행 전
- 여행 중
- 여행 완료

## 여행 생성 화면

입력 항목:

- 여행 제목
- 여행지
- 시작일
- 종료일
- 메모
- 국내/해외 여행 선택
- 기본 통화
- 환율
- 기본 지도 앱

유효성:

- 제목은 필수다.
- 여행지는 필수다.
- 시작일과 종료일은 필수다.
- 종료일은 시작일보다 빠를 수 없다.
- 국내 여행이면 환율 입력을 숨긴다.
- 해외 여행이면 환율 입력을 표시한다.

## 초대 코드 참여 화면

구성:

- 초대 코드 입력 필드
- 참여 버튼

동작:

- 유효한 초대 코드이면 해당 여행 멤버로 등록한다.
- 이미 참여한 여행이면 여행 상세 화면으로 이동한다.
- 잘못된 코드이면 오류 메시지를 표시한다.

## 여행 상세 화면

상단:

- 여행 제목
- 여행지
- 여행 기간
- 초대 코드 공유 버튼
- 설정 버튼

주요 탭:

- Day별
- 전체 일정
- 준비물

## Day별 일정 화면

구성:

- Day 선택 탭 또는 가로 스크롤 칩
- 선택된 Day의 날짜와 요일
- 일정 카드 목록
- 일정 추가 버튼

일정 카드 표시 정보:

- 시간
- 일정 제목
- 장소명
- 카테고리
- 예상 비용
- 원화 환산 금액
- 이동/소요 시간 메모
- 지도 열기 버튼
- 수정 버튼
- 삭제 버튼
- 위/아래 이동 버튼

일정이 없는 Day:

- 빈 상태 안내 문구
- 일정 추가 버튼

## 일정 추가/수정 화면

입력 항목:

- Day 또는 날짜
- 시간
- 일정 제목
- 장소명
- 주소 또는 지도 검색어
- 카테고리
- 예상 비용
- 통화
- 원화 환산 금액
- 이동/소요 시간 메모
- 상세 메모

동작:

- 저장 시 해당 Day 일정 목록에 반영한다.
- 날짜가 여행 기간 밖이면 저장할 수 없다.
- 장소명 또는 주소가 있으면 지도 열기 버튼을 활성화한다.

## 전체 일정 화면

구성:

- 여행 기간 전체 Day 목록
- Day별 일정 카드
- 일정 없는 Day도 표시

목적:

- 여행 전체 흐름을 한 화면에서 확인한다.

## 준비물 화면

구성:

- 준비물 입력 필드
- 추가 버튼
- 준비물 체크리스트

준비물 항목:

- 체크박스
- 준비물 이름
- 삭제 버튼

동작:

- 멤버 누구나 준비물을 추가할 수 있다.
- 멤버 누구나 체크 상태를 변경할 수 있다.
- 체크 상태 변경은 다른 멤버에게도 반영된다.

## 여행 설정 화면

구성:

- 여행 기본 정보 수정
- 기본 지도 앱 수정
- 기본 통화와 환율 수정
- 초대 코드 확인 및 재생성
- 멤버 목록
- 여행 삭제

권한:

- 여행 생성자는 모든 설정을 수정할 수 있다.
- 동행자는 기본 정보와 멤버 관리를 수정할 수 없다.
- 동행자는 기본 지도 앱을 볼 수 있으나, 여행 공용 설정 변경은 owner만 가능하게 한다.
